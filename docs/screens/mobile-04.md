## Mobile layout rules

- **Persistent floating header, public pages:** every `/help`, `/login`, `/enroll`
  screenshot shows the same rounded, card-like header pinned to the top of the
  viewport (logo + wordmark left, single hamburger IconButton right). This
  replaces the desktop nav bar's full link list (Home/About/Forum/Explore, per
  the design source doc) with a single hamburger control on mobile — presumably
  opening a Sheet/Drawer (the bundle includes `vaul` specifically for this).
- **Authenticated dashboard header is different:** `/dashboard/admin` uses a
  slimmer header — hamburger + role-label pill only, no logo/wordmark — distinct
  from the public-page header chrome.
- **Forms collapse to single column:** on `/enroll` Step 2 (Sign Up), First Name
  and Last Name are stacked vertically, not shown side-by-side — confirms desktop
  two-column form grids collapse to one column per row on mobile.
- **Paired action buttons stay side-by-side, not stacked:** "Back"/"Continue",
  "Back"/"Confirm Payment", "Back"/"Proceed to Verification" all render as two
  roughly equal-width buttons in a single row even at mobile width (2-column
  grid), rather than stacking.
- **Horizontal Stepper fits in one row:** the 5-step enrollment Stepper (Select
  Plan / Sign Up / Payment / Receipt / Verification) renders as one unbroken
  horizontal row of icon-circles + labels at mobile width, no horizontal scrolling
  or wrapping observed.
- **Dashboard stat/action cards use a 2×2 grid on mobile:** both the System
  Overview stat cards and the Quick Actions cards use a 2-column grid at this
  viewport width (likely 4-across on desktop, collapsing to 2-across on mobile).
- **Charts are full-width and touch-interactive:** the Recharts area/line combo
  and donut chart both span the full content width and support tap-to-reveal
  Tooltip (confirmed by the on-tap tooltip in screenshot 34).
- **No bottom tab bar and no FAB anywhere in this slice** — all navigation is via
  the header hamburger, inline links, or in-page primary/secondary buttons.
- **Bilingual content pattern (`/help` only):** every instructional string is
  rendered as English (bold, bright/white) directly above its Tagalog translation
  (smaller, muted gray) — a consistent two-line localization treatment, not a
  toggle/switcher.
- **Two distinct step-indicator components:** `/help` uses a **vertical** numbered
  timeline (circular number badges + connecting vertical line) for step-by-step
  instructions inside each accordion; `/enroll` uses a **horizontal** icon Stepper
  across the top of the whole 5-step wizard. These are visually and structurally
  different components — do not conflate them.
- **Disabled-button visual language:** disabled primary buttons ("Confirm
  Payment" before upload, "Enter My Account" before verification completes) keep
  the same green hue but at reduced saturation/opacity with muted text, rather
  than switching to a neutral gray — worth matching exactly for consistency.
- **Toast notifications stack at the bottom of the viewport** during the
  real-time verification wait (screenshot 30), independent of the static
  in-page checklist.
